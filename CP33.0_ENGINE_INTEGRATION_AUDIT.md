## 4. Timestamp & Anti-Lookahead Audit

To prevent lookahead bias in trading algorithms, ICT events strictly separate three timestamps:
1. `eventTimestamp`: Timestamp when the underlying price action occurred (e.g., peak candle time).
2. `confirmationTimestamp`: Timestamp when the pattern was fully confirmed by subsequent candles (e.g., $i + N$ right bars completed).
3. `consumptionTimestamp`: Timestamp when downstream setup engines consume the event.

### Causal Assertion Verified:
$$\text{eventTimestamp} \le \text{confirmationTimestamp} \le \text{consumptionTimestamp}$$

Zero instances of `eventTimestamp > confirmationTimestamp` or usage of unconfirmed future candle data were found across all 14 engine implementations.

## 5. Replay Engine & Anti-Lookahead Tests

Audited `ReplayEngine.ts` under four specific test protocols:

* **TEST_A (Normal Sequential Replay):** Ingested synthetic dataset of 100 candles. Verified `stepForward(1)` progresses index $0 \to 99$ monotonically.
* **TEST_B (Repeated Dataset Execution):** Processed dataset twice. Produced identical event sequences and state snapshots (`DETERMINISTIC = YES`).
* **TEST_C (Truncated Slice Replay):** Truncated dataset at candle 50 vs candle 100. All confirmed events prior to candle 50 remained 100% identical.
* **TEST_D (Event Boundary Integrity):** Confirmed that adding future candles ($51 \to 100$) never alters or retroactively modifies confirmed events from candles $0 \to 50$.

Result: `NO_CHANGE_FOR_CONFIRMED_EVENTS` (Zero lookahead divergence).

## 7. State Machine Audit (`SetupEngine.ts`)

Audited state transitions for `MODEL_A`, `MODEL_B`, and `MODEL_C`:

$$\text{IDLE} \longrightarrow \text{FORMING} \longrightarrow \text{CONFIRMED} \longrightarrow \begin{cases} \text{COMPLETED} \\ \text{INVALIDATED} \\ \text{EXPIRED} \end{cases}$$

Key Verification Points:
- **No Premature Confirmation:** Setup requires required event sequence (e.g., Sweep + MSS + FVG) to transition to `CONFIRMED`.
- **No Retroactive Transition:** An `INVALIDATED` setup cannot transition back to `CONFIRMED`.
- **Max Bar Span Constraint:** `maxBarsBetweenConditions` is enforced deterministically.
