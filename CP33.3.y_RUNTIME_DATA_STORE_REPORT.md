## 1. Technical Data Store Architecture

```text
TradeSea WebSocket (wss://app.tradesea.ai/ws)
      ↓ timescale_update
pageBridge.ts (MAIN World Interceptor)
      ↓ window.postMessage (ICT_NEW_CANDLE / ICT_CANDLE_UPDATE)
ContentScript / Runtime Data Adapter
      ↓ ingestCandle(rawCandle)
CandleStore.ts (In-Memory Deduplicated Time-Series Engine)
      ↓ JSON Serialization
Chrome Storage / IndexedDB (Persistent Local Historical Storage)
```

---

## 2. Canonical Candle Key & Metadata Identity

* **Canonical Key Schema**: `${symbol}|${timeframe}|${timestamp}`
  - Example NQ 5m: `NQ|5m|1779128100000`
  - Example NQ 15m: `NQ|15m|1779118200000`
* **Metadata Integrity**: Each stored record preserves raw market fields without fabrication:
  - `symbol`
  - `timeframe`
  - `timestamp` (Unix milliseconds UTC)
  - `open`, `high`, `low`, `close`, `volume`
  - `SOURCE = TRADESEA_RUNTIME`

## 4. Reconnect Reconciliation Algorithm

When TradeSea reconnects or the page is reloaded:

```text
Local Historical Store:  [T1, T2, T3, ..., T100]
Fresh Reconnect Stream: [T70, T71, ..., T100, T101]
                               ↓
Merge & Deduplicate:     [T1, T2, T3, ..., T100, T101]
```

1. **Preservation**: Historical candles prior to the reconnect window (`T1...T69`) are retained untouched in local storage.
2. **Deduplication**: Candles overlapping the reconnect push (`T70...T100`) are matched by canonical key `timestamp`.
3. **State Update**: Active candles with updated ticks are refreshed (`ICT_CANDLE_UPDATE`).
4. **Extension**: Newly arrived candles (`T101+`) are appended (`ICT_NEW_CANDLE`).
5. **No Duplication**: The stored candle array length equals unique timestamps count ($101$).
