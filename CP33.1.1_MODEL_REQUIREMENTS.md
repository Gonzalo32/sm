# CP33.1.1 — Code Model Requirements Specification

**Audit Date:** 2026-09-29  
**Source File:** `core/ict/models/PredefinedModels.ts` & `core/ict/setups/SetupEngine.ts`  
**Purpose:** Formal Specification of Implemented Code Model Preconditions for Audit Alignment

---

## 1. Model Precondition Specifications

### Model A (`MODEL_A`)
- **Required Events / Conditions:**
  1. `LIQUIDITY_SWEEP` (or active `BSL`/`SSL` sweep)
  2. `MSS_CONFIRMED` (Market Structure Shift)
  3. `FVG_CONFLUENCE` (`FVG_CREATED` with $size \ge 0.25$ pts)
- **Sequence Mode:** `ORDERED` (Event 1 $t_1 \le$ Event 2 $t_2 \le$ Event 3 $t_3$)
- **Max Bar Span:** $\max(\text{candleIndex}) - \min(\text{candleIndex}) \le 50$ bars
- **Validation Rule:** All 3 required events must be present, ordered causally, and within 50 bars.

---

### Model B (`MODEL_B`)
- **Required Events / Conditions:**
  1. `LIQUIDITY_SWEEP` (or active `BSL`/`SSL` sweep)
  2. `BOS_CONFIRMED` (Break of Structure by Close)
  3. `ORDER_BLOCK_CONFLUENCE` (`ORDER_BLOCK_CREATED` Variant B with FVG)
- **Sequence Mode:** `ORDERED` (Event 1 $t_1 \le$ Event 2 $t_2 \le$ Event 3 $t_3$)
- **Max Bar Span:** $\max(\text{candleIndex}) - \min(\text{candleIndex}) \le 50$ bars
- **Validation Rule:** All 3 required events must be present, ordered causally, and within 50 bars.

---

### Model C (`MODEL_C`)
- **Required Events / Conditions:**
  1. `HTF_TREND_ALIGNED` (Higher Timeframe Trend Confluence)
  2. `MSS_CONFIRMED` (Market Structure Shift)
  3. `DISPLACEMENT` (`DISPLACEMENT` event with `bodyRatio >= 0.60`, `rangeMultiplier >= 1.50`)
- **Sequence Mode:** `UNORDERED` (Conditions must be satisfied within max bar span)
- **Max Bar Span:** $\max(\text{candleIndex}) - \min(\text{candleIndex}) \le 50$ bars
- **Validation Rule:** All 3 required conditions must be satisfied within 50 bars.

---

## 2. Setup Validation Audit Criteria

A setup generated by `SetupEngine.ts` is classified as `VALID_STRUCTURE` if and only if:
1. `MODEL_REQUIREMENTS_SATISFIED` = `YES`
2. `TIMESTAMP_ORDER_VALID` = `YES` ($\text{eventTimestamp} \le \text{confirmationTimestamp} \le \text{consumptionTimestamp}$)
3. `EVENTS_AVAILABLE_AT_CONSUMPTION` = `YES`
4. `NO_DUPLICATE_CONSUMPTION` = `YES`
5. `NO_FUTURE_EVENT_USED` = `YES`
6. `STATE_TRANSITION_VALID` = `YES` ($\text{FORMING} \to \text{CONFIRMED} \to \text{COMPLETED}/\text{INVALIDATED}/\text{EXPIRED}$)
