## 2. Hypothesis Evaluation

We evaluated five structural hypotheses regarding what triggers the 31-candle payload:

* **Hypothesis A** (`CLIENT` $\rightarrow$ explicit historical request $\rightarrow$ `SERVER` $\rightarrow$ `timescale_update` 31 candles):  
  *Evaluation*: `NOT_OBSERVED`. No explicit client payload requesting `from`/`to`/`count` parameters for historical candles was observed prior to the `timescale_update` frame.
* **Hypothesis B** (`CLIENT` $\rightarrow$ session/series init $\rightarrow$ `SERVER` automatic push $\rightarrow$ `timescale_update` 31 candles):  
  *Evaluation*: **`HYPOTHESIS_B = MOST_LIKELY`** (`HISTORY_TRIGGER_TYPE = SESSION_INITIALIZATION_PUSH`). When the TradeSea client initializes the chart component, it establishes the WebSocket connection and creates a series session identifier. TradeSea's server automatically pushes the initial viewport bar array (31 candles) inside the first `timescale_update` series frame.
* **Hypothesis C** (`CLIENT` $\rightarrow$ TradingView internal series subscription $\rightarrow$ `timescale_update`):  
  *Evaluation*: `SUBSCRIPTION_RELEVANCE = YES`. The series creation message acts as a stream subscription rather than an explicit backfill data request.
* **Hypothesis D** (Chart viewport state $\rightarrow$ backend auto push):  
  *Evaluation*: Partially supported alongside Hypothesis B.
* **Hypothesis E** (Alternative mechanism):  
  *Evaluation*: Not supported by observed evidence.
