# CP33.1.5 — Runtime Memory Window & 60-Day Lookback Specification

**Audit Date:** 2026-09-29  
**Scope:** Specification of In-Memory Time Series Storage & 60-Day Lookback Window Pruning  
**Production Mutation:** NONE (Read-Only Audit)

---

## 1. Lookback Window Specifications

- **Target Lookback Period:** `REQUESTED_LOOKBACK_DAYS = 60`
- **Max Memory Window Duration:** $60 \text{ days} \times 24 \times 60 \times 60 \times 1000 = 5,184,000,000 \text{ ms}$.
- **Storage Strategy:** `MEMORY_ONLY` (Bounded in-memory time series inside `CandleStore`).
- **File Persistence Policy:** No automatic disk saving in CSV, JSON, or SQLite required for indicator operation.

---

## 2. Partial Availability Handling Policy

If a market source returns fewer than 60 days of historical data (e.g. 17 days available):

```text
REQUESTED_LOOKBACK_DAYS = 60
ACTUAL_AVAILABLE_LOOKBACK_DAYS = 17.0
NO_DATA_FABRICATION = YES
```

- **Rule:** The system accepts the 17 available days without generating mock candles, duplicating bars, or padding the dataset with synthetic data.
- **Reporting:** `getMemoryWindowStatus()` returns `requestedLookbackDays: 60` and `actualAvailableLookbackDays: 17.0`.

---

## 3. Automated Window Pruning

- As new candles are ingested, `CandleStore.pruneOldCandles()` automatically discards any candle whose timestamp is older than `latestTimestamp - (60 * 24 * 60 * 60 * 1000)`.
- Discarded candles are counted under `prunedCandlesCount` and purged from RAM to prevent memory leaks.
