## 1. Runtime Data Flow Architecture

The live market data pipeline is structured as an un-mutated, decoupled data processing chain:

```text
  [ Market Data Source / WS Stream ]
                 │
                 ▼
     [ MarketDataAdapter.ts ] ──► (Validation & Synthetic Source Blocking)
                 │
                 ▼
       [ CandleStore.ts ] ──────► (In-Memory 60-Day Window Storage & Pruning)
                 │
                 ▼
       [ ICTEngine.ts ] ────────► (Causal ICT Pipeline Processing)
                 │
                 ▼
  [ Realtime WS Tick Handler ] ──► (Forming Update / Confirmed Bar Transition)
                 │
                 ▼
   [ Visual Adapter / Canvas / HUD ]
```

---

## 2. Decoupling & Module Boundaries

1. **Pure TypeScript Core (`core/market/`)**:
   - `Candle.ts`: Strongly-typed candle structures and event contracts.
   - `CandleValidator.ts`: Pure geometric and timestamp validation logic.
   - `CandleStore.ts`: In-memory time series storage, lookback pruning, event emitter.
   - `MarketDataAdapter.ts`: Source adapter, connection state manager, synthetic blocker.
   - **Zero DOM / Chrome API Dependencies:** Fully testable in headless Node environment.

2. **Browser Extension Layer (`extension/content/pageBridge.ts`)**:
   - WebSockets frame interceptor (TradingView / Rithmic WS).
   - DOM symbol/timeframe context detector.

---

## 3. Causal Preservation Protocol

- **Timestamp Ordering:** `eventTimestamp <= confirmationTimestamp <= consumptionTimestamp`.
- **Forming vs Confirmed Candles:**
  - `ICT_CANDLE_UPDATE`: Formed by intrabar tick updates for current active candle ($t_{\text{candle}} = t_{\text{latest}}$). No confirmed ICT structure events emitted from unconfirmed candle closes.
  - `ICT_CANDLE_CLOSE` & `ICT_NEW_CANDLE`: Emitted sequentially when a new candle timestamp arrives ($t_{\text{candle}} > t_{\text{latest}}$).
- **Retroactive Immutability:** Confirmed historical setup events cannot be modified or deleted by subsequent realtime ticks.
