# CP33.1.5 — Reconnection & Gap Handling Policy Report

**Audit Date:** 2026-09-29  
**Scope:** WebSocket Disconnect Recovery, Timestamp Deduplication & Gap Handling  
**Production Mutation:** NONE (Read-Only Audit)

---

## 1. Connection State Lifecycle

`MarketDataAdapter` manages four connection states:
- `DISCONNECTED`: Initialized or feed connection lost.
- `CONNECTED`: Active historical load or realtime stream ingestion.
- `RECONNECTING`: Socket recovery in progress.
- `ERROR`: Invalid data payload or synthetic runtime violation.

---

## 2. Reconnection Recovery Algorithm

When a WebSocket stream drops and reconnects:

1. **Capture Last Timestamp:** Retrieve $t_{\text{last}} = \text{store.getLatestCandle().timestamp}$.
2. **Request Gap Fill:** Query data provider for missing bars where $t > t_{\text{last}}$.
3. **Deduplicate Segment:** Filter returned missing bars so that only candles with $t \ge t_{\text{last}}$ are processed.
4. **Active Bar Update:** If $t = t_{\text{last}}$, update current active forming bar (`ICT_CANDLE_UPDATE`).
5. **Sequential Progression:** If $t > t_{\text{last}}$, emit close for previous bar (`ICT_CANDLE_CLOSE`) and append new bar (`ICT_NEW_CANDLE`).
6. **No Time Regressions:** Reject any out-of-order candles with $t < t_{\text{last}}$.

---

## 3. Gap Detection vs Fabrication Policy

- **Expected Session Gap:** Standard market closures (weekends, session breaks) or missing feed bars ($t_k - t_{k-1} > \text{expectedIntervalMs} \times 1.5$) are recorded under `gapEventsCount`.
- **No Data Fabrication:** Missing candles are **never** filled with interpolated prices, zero-volume bars, or synthetic sine curves.
