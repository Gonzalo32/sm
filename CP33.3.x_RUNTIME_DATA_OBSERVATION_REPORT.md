## 2. Distinction Audit (A, B, C, D)

1. **A. Visible Candles**: 10 to 18 candles displayed on screen inside current chart window boundaries depending on zoom.
2. **B. Loaded Series Data**: 31 candles loaded in browser memory from the initial WebSocket `timescale_update` payload.
3. **C. Expandable Data via Interaction**: Timeframe switching loads a fresh 31-candle series tailored to the new timeframe. Scrolling left does **NOT** expand the series.
4. **D. Non-existent / Unavailable Data**: Historical bars older than 31 candles on intraday timeframes (e.g. >2.5 hours on 5m) cannot be obtained from TradeSea's native WebSocket stream.

## 3. WebSocket Traffic & `pageBridge.ts` Observations

* **WebSocket Endpoint**: `wss://app.tradesea.ai/ws`.
* **Payload Structure**: Framing format `~m~len~m~json` carrying `m: "timescale_update"`.
* **Series Delivery**: Object `p[1]` contains series array `s` holding `[time, open, high, low, close, volume]`.
* **`pageBridge.ts` Integration**: Chrome Extension `pageBridge.ts` successfully intercepts WebSocket `message` events, parses `timescale_update`, extracts bar data, and posts `ICT_NEW_CANDLE` / `ICT_CANDLE_CLOSE` messages to the extension runtime.
