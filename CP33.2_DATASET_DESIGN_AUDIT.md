## 4. Dataset Purpose & 11 Core Design Answers

### 1. Instrument Scope
* **`PRIMARY_INSTRUMENT = NQ`** (E-mini Nasdaq-100 Futures). Primary liquidity benchmark.
* **`SECONDARY_INSTRUMENT = MNQ (ECONOMICALLY_EQUIVALENT)`** (Micro E-mini Nasdaq-100 Futures).
  - *Technical Finding*: NQ and MNQ track the identical underlying index with 1:1 price action and identical point structure. MNQ is treated as economically equivalent, NOT as an independent asset class.

### 2. Timeframe Scope
* **`PRIMARY_TIMEFRAME = 5m`** (5-Minute Intraday Benchmark).
* **`SECONDARY_TIMEFRAMES = 1m, 15m`**. Evaluated under a structured multi-timeframe protocol to test pattern stability across scale.

### 3. Historical Period Selection
* Unseen multi-week market blocks selected from periods strictly outside the CP31/CP32 calibration window.
* Stratified across: High Volatility (FOMC/CPI releases), Low Volatility (summer consolidation), Bullish Trend, Bearish Trend, and Sideways Ranging market regimes.

### 4. Required Case Count & Rationale
* **Minimum Technical Case Count**: 50 non-overlapping cases per instrument/timeframe slice.
* **Validation-Design Case Count**: **300 independent cases** (150 positive candidate windows, 150 neutral/negative control windows).
* *Rationale*: 300 non-overlapping cases provide adequate statistical representation across 5 volatility regimes without introducing window redundancy.

### 5. Case Selection Rule
* Stratified random sampling using pre-registered timestamp windows.
* Zero manual post-hoc selection ("cherry-picking"). Every window falling into pre-registered time slots must be included regardless of detection outcome.

### 6. Development / Test Data Separation
* **2-Stage Split Architecture**:
  - `CALIBRATION_DATASET`: CP32.6 300 cases (used strictly for past engine development).
  - `INDEPENDENT_TEST_DATASET`: Future unseen multi-week continuous blocks.
* *Note on 3-Way Split*: A third `FINAL_TEST` split is technically unnecessary at this stage because no parameter optimization is allowed. Introducing a 3rd set would needlessly fragment sample size.

### 7. Temporal Leakage Control
* **`TEMPORAL_ISOLATION_RULE = PASS`**. Hard timestamp cutoff: The test set must be drawn exclusively from historical dates strictly after (or before) the calibration dataset timestamps.

### 8. Overlap Control Rule
* **`MINIMUM_TEMPORAL_SEPARATION = 20_CANDLES_5M (100_MINUTES)`**.
* Adjacent or overlapping windows sharing $>0$ candles are strictly forbidden from being counted as distinct independent cases.

### 9. Labeling Protocol
* **`LABEL_INDEPENDENCE_RULE = PASS`**.
* Double-blind human review protocol: Human labelers view anonymized static OHLC candle charts in `viewer.html` without detector overlay lines, model scores, or indicator hints.

### 10. Sealing Protocol
* SHA-256 hash checksum generated over `cases.json`, `labels.json`, and `manifest.json`.
* **`SEALED_DATASET_MODIFICATION = PROHIBITED`**. Any post-seal corrections require a new versioned dataset (`v2.0`).

### 11. Permitted vs. Prohibited Metrics Classification
* See Section 6 for full breakdown.

## 5. Leakage & Contamination Controls Audit

| Leakage Type | Hazard Description | Control Protocol | Audit Status |
| :--- | :--- | :--- | :---: |
| **Future Candle Leakage** | Engine accessing $t+k$ candles during replay | `getCurrentSlice()` returns `slice(0, idx + 1)` | **PASS** |
| **Future Event Leakage** | Caching future BOS/FVG events in replay state | Detector runs statefully from index 0 forward | **PASS** |
| **Label Leakage** | Detector output displayed to human labeler | Blind review interface hides all engine outputs | **PASS** |
| **Parameter Leakage** | Tuning `bodyRatio` or `fvgMinSizePoints` on test data | Parameter freeze strictly enforced (`MODELS_MODIFIED=NO`) | **PASS** |
| **Case Selection Leakage** | Selecting windows because ICT patterns look "clean" | Pre-registered timestamp grid sampling | **PASS** |
| **Temporal Overlap** | Consecutive cases sharing price candles | 20-candle minimum temporal buffer enforced | **PASS** |
| **Cross-Dataset Contamination** | Re-using CP32 calibration cases in CP33 test set | Strict timestamp exclusion set against CP32 | **PASS** |

### Permitted Descriptive Audit Metrics (`PERMITTED`)
