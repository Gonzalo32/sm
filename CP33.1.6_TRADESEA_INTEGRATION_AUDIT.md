## 1. Executive Discovery Summary

An exhaustive empirical investigation was conducted across `extension/`, `core/`, `scripts/`, `tests/`, and project documentation to determine how TradeSea receives market data and whether live real-market feeds are currently active.

---

## 2. Forensic Analysis of Data Mechanisms

### A. TradeSea / TradingView WebSockets (`extension/content/pageBridge.ts`)
- **Mechanism:** Listens to `window.WebSocket` message events inside the browser DOM (MAIN world) when injected into `https://app.tradesea.ai/*`.
- **Message Parsing:** Intercepts TradingView protocol frames (`~m~...~m~`) and timescale updates (`timescale_update`), extracting OHLC arrays `[timestamp, open, high, low, close, volume]`.
- **DOM Context Detection:** Inspects DOM elements (`.symbol-title`, `[data-name="legend-source-title"]`, `.resolution-button`) to detect symbol and timeframe changes (`MNQ`, `NQ`, `1m`, `5m`, etc.).
- **Headless Execution Status:** In a headless test environment or outside active browser pages, no live WebSocket connection exists.
- **Classification:** **`LIVE_SOURCE_NOT_CONNECTED`**

### B. Rithmic Integration
- **Mechanism:** Mentioned as architectural target in historical phase reports (`PHASE_0_INVESTIGATION_REPORT.md`, `PHASE_1_CHECKPOINT_REPORT.md`).
- **Code Inspection:** Zero active Protobuf socket parsers, Rithmic REST endpoints, or Rithmic authentication tokens exist in the codebase.
- **Classification:** **`ARCHITECTURE_ONLY`**

### C. Historical REST Feed
- **Mechanism:** `runHistoricalScanProbe()` in `pageBridge.ts` is an internal test probe simulating feed limit responses.
- **Unauthenticated REST API:** No public, unauthenticated external TradeSea REST historical API endpoint is exposed or documented without an active authenticated browser session.
- **Classification:** **`ARCHITECTURE_ONLY`**

## 3. Data Integration Answers

1. **Where does TradeSea get data?** TradingView datafeed WebSockets and Rithmic price streams during active user sessions on `app.tradesea.ai`.
2. **Can the extension access this data?** YES, via browser extension DOM WebSocket interception (`pageBridge.ts`).
3. **Does history exist?** Historical data is provided in-session via TradingView timescale updates when charts load.
4. **Does realtime exist?** YES, via intrabar timescale updates during active trading sessions.
5. **How much history is available?** Dependent on active browser chart session limits (e.g. ~5,000 bars max per request).
6. **In what format does it arrive?** TradingView JSON array frames (`[time, open, high, low, close, volume]`).
7. **How are MNQ/NQ identified?** Symbol title string from DOM / TV active chart object (`chart.symbol()`).
8. **How are 1m/5m/15m identified?** Resolution button string from DOM / TV active chart object (`chart.resolution()`).
9. **Can `MarketDataAdapter` be fed directly?** YES. `ICTPipelineCoordinator` has been updated to route both historical window loads and realtime stream updates directly through `MarketDataAdapter`.
10. **Technical limitations:** Requires active authenticated browser session on `https://app.tradesea.ai/*`.
