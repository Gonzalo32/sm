## 3. Visual Contract Implemented

The visual contract translates `ICTSetup` objects into renderable `VisualObject` primitives (`VisualMarker`, `VisualLine`, `VisualRectangle`) according to strict domain rules:

### A. Directional Markers
* **Confirmed Bullish Setup (`CONFIRMED` + `LONG`):**
  * Visual Type: `BUY_SETUP`
  * Primitive: `VisualMarker` (`shape: 'TRIANGLE_UP'`)
  * Color: `#22c55e` (Vibrant Green)
  * Label: `BUY SETUP [${modelId}]`
  * Z-Index: `60`
* **Confirmed Bearish Setup (`CONFIRMED` + `SHORT`):**
  * Visual Type: `SELL_SETUP`
  * Primitive: `VisualMarker` (`shape: 'TRIANGLE_DOWN'`)
  * Color: `#ef4444` (Vibrant Red)
  * Label: `SELL SETUP [${modelId}]`
  * Z-Index: `60`

### B. Optional Geometric Levels (Derived from Actual Market State)
* **Entry Zone (`RECTANGLE`):**
  * Derived from the confluent Fair Value Gap (`fvg.highPrice`, `fvg.lowPrice`) or Order Block (`ob.highPrice`, `ob.lowPrice`).
  * Styled with semi-transparent fill (`opacity: 0.3`) and border colored according to setup direction.
  * Omitted if no valid confluent FVG or OB exists.
* **Invalidation Level (`LINE` DASHED):**
  * Derived from the swept liquidity extreme price (`sweep.extremePrice`) or opposing swing point.
  * Styled with dashed line style (`lineStyle: 'DASHED'`, `#f43f5e`, `lineWidth: 1.5`).
  * Validated to confirm structural orientation (below entry for LONG, above entry for SHORT). Omitted if missing or orientational criteria fail.
* **Target Level (`LINE` DOTTED):**
  * Derived from the nearest opposing un-swept liquidity level in `state.liquidityLevels` (BSL for LONG, SSL for SHORT).
  * Styled with dotted line style (`lineStyle: 'DOTTED'`, `#38bdf8`, `lineWidth: 1.5`).
  * Omitted if no un-swept opposing liquidity level exists.

### C. Strict Lifecycle State Handling
* `CONFIRMED`: Renders active entry markers and associated geometric levels.
* `WATCHING` and `FORMING`: **Strictly excluded** from confirmed entry signals. Zero entry markers are produced.
* `INVALIDATED`, `EXPIRED`, and `COMPLETED`: **Immediately pruned** from active drawings. They do not remain visually active on the chart.
* **Context Mismatches:** Setups whose `symbol` or `timeframe` do not match the active chart state are rejected immediately (0 drawings emitted).
* **Missing/Invalid Coordinates:** If finite prices or timestamps cannot be resolved, the adapter **fails closed** and returns null rather than fabricating arbitrary prices or win rates.

## 4. Pipeline Integration Details

In `extension/content/ICTPipelineCoordinator.ts`:
1. `SetupEngine.evaluateSetups(state, events, confluences)` evaluates declarative setup models up to the current candle index.
2. The evaluated `setups` collection is passed to `this.visualAdapter.adaptStateToVisuals(state, events, candidateContext, setups)`.
3. `VisualAdapter` validates context, filters for `CONFIRMED` status, extracts factual price levels, deduplicates against active registry, and generates `VisualObject[]`.
4. The generated visual objects are merged with existing structural drawings (Swings, BOS, MSS, Sweeps, FVGs, OBs, and Context badges) and delivered to `CanvasRenderer.updateVisuals()`.
5. On instrument or timeframe change (`coordinator.setContext()`), `this.visualAdapter.resetContext()` is invoked alongside `this.renderer.clear()`, preventing stale drawings on the new chart.

---

## 5. Lifecycle and Deduplication Behavior

* **Registry Key:** `${setup.symbol}:${setup.timeframe}:${modelId}:${setup.direction}`
* **In-Place Updates:** Subsequent evaluations of the same setup replace the prior visual objects in the registry. Repeated evaluations on consecutive ticks maintain exactly one active annotation entity.
* **State Transition:** When an active setup transitions to `INVALIDATED` or `EXPIRED`, its key is removed from `setupVisualRegistry`, instantly removing the marker from the overlay.
* **Symbol Switching:** Changing symbols (e.g. `MNQ` $\rightarrow$ `ES`) clears the entire registry, guaranteeing zero cross-symbol drawing bleed.

---

## 6. Coordinate Mapping and Chart Rendering

* Coordinates are mapped through `CoordinateTranslator`:
  * X coordinates: `translator.indexToX(candleIndex, timestamp)`.
  * Y coordinates: `translator.priceToY(price)`.
* Canvas rendering is performed by `CanvasRenderer` on the transparent overlay (`#ict-canvas-overlay`) using `pointer-events: none` and `z-index: 9999`.
* Visual annotations are strictly informational drawings on the transparent canvas and contain no interactive order buttons, clickable trade triggers, or order execution APIs.
