## 3. Formal Candle Identity & Lifecycle Model

### A. Canonical Candle Identity Key
The unambiguous composite identity key used across memory, deduplication, storage, and recovery is:

$$\mathbf{CandleIdentity = \text{symbol} \mid \text{timeframe} \mid \text{marketTimestamp}}$$

* *Example NQ 5m*: `NQ|5m|1779128100000`
* *Example NQ 15m*: `NQ|15m|1779118200000`

### B. State Machine Lifecycle
$$\text{RECEIVED} \longrightarrow \text{NEW} \longrightarrow \text{OPEN} \longrightarrow \text{UPDATED} \longrightarrow \text{CLOSED} \longrightarrow \text{PERSISTED}$$

* **Open Candle Updates**: While timestamp $T$ remains active, incoming tick updates modify OHLCV in-place (`high_new >= high_old`, `low_new <= low_old`).
* **Closed Candle Inference**: In streaming WebSocket feeds, TradeSea does not emit explicit "closed" flags. A bar at timestamp $T$ is inferred as **`CLOSED`** when a newer bar with timestamp $T+1$ ($T+1 > T$) is ingested into `CandleStore`.
* **Closed Bar Immutability**: Once closed, historical bar $T$ is immutable. Out-of-order updates attempting to overwrite closed bars are rejected with an explicit error (`Out of order timestamp received`).
